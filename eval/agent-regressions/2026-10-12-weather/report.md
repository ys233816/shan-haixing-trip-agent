# Agent 迭代记录：天气 / 闭馆局部调整

## 口径

本记录把 Agent 版本冻结在同一组 12 条天气、闭馆、重复渲染专项用例上。用例来自 A09 暴雨失败案例及其相邻边界场景，使用离线受控 fixture，不调用付费大模型；另用 Playwright 在桌面 1365×900 和手机 390×844 视口各重放 A09，并检查刷新后的会话状态。R01–R12 的明细在各版本 `results.json`，浏览器证据在 `browser-verification.json` 和各版本 PNG/JSON。

## 结果

| Agent 版本 | 通过 | 总数 | 专项回归通过率 | 相对上一版 |
|---|---:|---:|---:|---:|
| V1 修复前 | 2 | 12 | 16.67% | - |
| V2 保留暂停结果 | 8 | 12 | 66.67% | +50.00 个百分点 |
| V3 最终版 | 12 | 12 | 100.00% | +33.33 个百分点 |

V3 相比 V1 提升 **83.33 个百分点**（16.67% → 100.00%）。这是天气 / 闭馆专项指标，不能写成 36 条全量任务完成率。

## 36 条历史评测基线

已保存的 36 条混合历史记录中，任务完成率为 **7/36 = 19.44%**；失败 29 条里主要故障层为 **L3：18/29 = 62.07%**。L1 为 8 条，L4 为 3 条，L2 为 0 条。该汇总包含不同时间的截图和真实运行，且评分人为助手证据复核，不是同一冻结版本的独立盲评，因此只作为历史基线，不能和上面的 V1–V3 专项率直接相减。

## 修复内容

1. 天气 / 闭馆调整写入按日期保存的移除记录；渲染补齐时跳过该日期已暂缓或移除的景点，重复渲染和刷新不再恢复它们。
2. 没有确认安全室内候选时保留自由活动 / 休息，不用新的户外景点填满日程。
3. 候选替换增加事件约束校验，拒绝模型返回的不合格候选，并防止已在其他日期或已移除候选重复进入。
4. 暴雨 / 强对流天气显示安全提醒、用户报告未独立核实提示、官方预警和景区公告核对提示；Markdown 导出同步包含这些信息。

## 简历可用表述

> 针对旅行 Agent 的 ReAct 天气 / 闭馆局部调整链路，基于 A09 暴雨失败样本构建 12 条固定回归集：定位到渲染补齐重新加入已暂停户外景点的 L3 缺陷，增加日期级排除状态、候选安全约束、自由时间回退和强天气安全提示；专项回归通过率由 V1 的 16.67% 提升至 V3 的 100%，提升 83.33 个百分点，并在桌面 / 移动端及刷新恢复场景验证通过。

不要把“36 条历史基线 19.44%”和“专项回归 V1–V3”混写成同一条曲线；若要声称全量 V3 提升，需要用同一版本协议重跑 36 条并人工复核。
