# 山海行：中国大陆旅行规划助手

一个面向中国大陆景区的本地旅行规划 Agent 原型。使用原生 Web 页面和 Node.js 服务，可选接入 DeepSeek 等兼容模型接口；运行应用无需安装 npm 依赖。服务端负责景点知识检索和高德天气、路线查询，API Key 保存在 `.env`，不会发送到浏览器代码。

## 方案

采用 Plan-and-Execute 先生成逐日框架，再检索景点并检查时长、预算、偏好和重复项，便于逐项校验。遇到天气或闭馆变化时，以 ReAct 的“观察变化、调用工具、检查结果”方式局部调整，保留其他日期的安排。模型输出受本地候选和规则校验约束，工具或模型不可用时展示限制并回退。

短期记忆保存本次行程需求及调整状态；长期记忆需主动开启，仅保存偏好、节奏和步行接受度。检索使用字段、关键词及字符片段匹配，没有使用向量嵌入。

## 启动

需要 Node.js 18 或更高版本。

1. 在高德开放平台创建 Web 服务应用，确认已开通地理编码、天气和路线相关服务，并取得 Web 服务 Key。
2. 将 `.env.example` 复制为 `.env`，在 `AMAP_WEB_KEY=` 后填写 Key。不要把真实 Key 写进代码或提交到代码仓库；`.env` 已被 `.gitignore` 排除。
3. 如需启用大模型编排，在 `.env` 中填写 `LLM_BASE_URL`、`LLM_MODEL` 和 `LLM_API_KEY`。支持 OpenAI 兼容的 Chat Completions 接口，例如：

   - DeepSeek V4 Flash：`LLM_BASE_URL=https://api.deepseek.com`，`LLM_MODEL=deepseek-v4-flash`
   - 通义千问：`LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`，`LLM_MODEL=qwen-plus`

   API Key 只填在本机 `.env` 中，不要放进网页代码或聊天消息。未配置时，应用自动使用本地规则规划。启用后，本次行程的目的地、日期、预算、偏好及候选景点信息会发送给你配置的模型服务商。
4. 在项目目录运行：

   ```powershell
   npm start
   ```

   也可以运行 `node server.js`；Windows 用户可双击 `启动旅行规划助手.bat`。

5. 在浏览器打开 <http://127.0.0.1:4173/>。天气与路线查询要通过这个地址使用；直接打开 `index.html` 文件不会连接本地 API。

停止服务时，在运行服务的终端按 `Ctrl+C`。

## 已实现功能

- 结构化收集目的地、日期、天数、人数、预算、偏好、节奏和步行接受度。
- 配置 OpenAI 兼容模型后，由模型在本地知识库候选景点中编排行程；服务端校验景点编号、每日数量及重复项。未配置或调用失败时回退到规则规划。
- 单个景点发生天气影响或闭馆变化时，模型只从未排入其他日期的知识库候选中建议当天替代项；服务端校验候选编号。没有安全替代项时会暂缓该景点；模型不可用时回退本地规则。
- 雨雪或恶劣天气影响多站行程时，逐一检查当天户外及低雨天适合度景点，优先用未排入其他日期的室内候选替换；闭馆事件仍只针对用户指出的景点。
- 从 `中国大陆景点知识库_初版.md` 读取景点资料，按城市、字段、关键词和字符片段做本地混合检索。
- 用可解释的规则生成逐日行程骨架；出行日期落在天气服务的预报范围内时，查询天气并在雨雪天气优先安排尚未排入计划的室内景点。
- 每日开始时段根据建议游览时长、午餐休息和路段交通预留动态推算；已查询路线后使用地图返回的时长调整后续景点时间，并在下载文件中保留。
- 提供可调整参数的预算估算，包括住宿、餐饮、市内交通、已知门票和机动预留；区分人均与总预算、天数与住宿晚数，未知票价单独披露。已估支出超预算时展示差额，并由用户确认预算或取舍后继续规划。
- 缺少必要信息或需求冲突时，集中澄清最多三组问题；修改请求后清理旧计划，避免较早返回的请求覆盖新需求。
- 按偏好检查主行程覆盖，兼顾游览时长、步行强度、夜游和轮椅需求；无法满足时显示缺口，无障碍设施仍需向景区核实。
- 可将当前行程和预算明细下载为 Markdown 文件；局部调整后下载的是调整后的版本。
- 可查询高德天气，并按用户输入的两个地点查询步行、驾车或公共交通路线。路线结果会展示地图解析出的地址，用户应检查是否匹配。
- 每日展示景点游览、转场和约 60 分钟午餐预留的总占用时长；每日有两个及以上景点时，可按需查询景点间路线，用地图路段时间更新估算并提示日程是否偏紧。未查全路线时，缺失路段暂按每段 45 分钟估算；估算不含排队、候车、额外休息及景区内交通。公共交通路线返回的费用会作为参考展示，不与市内交通日预算重复相加。查询只在用户点击后发起，成功后会保存在本次会话并写入行程下载文件。
- 景点卡片展示知识库中的开放时间、预约要求、票价及官方来源链接；北京条目标注信息核验日期，短期公告或价格政策可能变化，行前仍须复核官网。
- 用户报告天气或闭馆变化后，尝试只调整受影响日期；若需与另一日交换景点，会明示受影响的日期。无可核实替代项时，将受影响景点移出可执行计划。
- 短期行程状态存于当前浏览器会话，可从行程页清除本次行程及该标签页的恢复记录。长期只在用户主动启用时，将偏好、节奏和步行接受度存于本机浏览器 `localStorage`；不保存预算、日期、目的地、人数或特殊要求。

## 本地 API

- `GET /api/health`：服务状态、Key 是否配置、知识库条目数量。
- `GET /api/llm/status`：检查模型配置状态，不返回 API Key。
- `POST /api/llm/plan`：根据需求、天气摘要和景点候选生成每日景点编号。
- `POST /api/llm/react`：根据用户报告的天气或闭馆情况建议局部替换景点。
- `GET /api/attractions?q=雨天%20室内&city=杭州&limit=5`：搜索景点资料。可选 `indoor`、`rain` 字段筛选。
- `GET /api/weather?city=杭州`：查询天气预报。
- `GET /api/route?city=杭州&origin=西湖区湖滨步行街&destination=西湖区灵隐寺&mode=transit`：查询路线；`mode` 可设 `walking`、`driving` 或 `transit`。

## 更新景点知识库

在 Markdown 文件中，每个景点使用一个二级标题，并用 `- 字段：内容` 编写资料。可参考已有条目的字段：城市、区域、类型、室内外、建议时长、开放时间、预约要求、门票、开放时间来源、预约票务来源、官方信息核验日期、雨天适合度、步行强度和附近景点。新增或更新资料保存后，服务会从文件读取；无需重启。

## 评测与迭代

`eval/` 保存测试集、评分规则、评委 Prompt、人工复核记录及迭代指标。36 条历史样本覆盖典型、边界和对抗场景；按输入、上下文、规划、执行四层归因。

| 专项回归 | 固定样本数 | 改进前 | 改进后 |
| --- | ---: | ---: | ---: |
| 首次规划约束 | 17 | 3/17（17.65%） | 17/17（100%） |
| 预算口径与估算 | 22 | 3/22（13.64%） | 22/22（100%） |
| 偏好落实 | 18 | 2/18（11.11%） | 18/18（100%） |
| 缺项澄清与状态一致性 | 12 | 1/12（8.33%） | 12/12（100%） |

以上是固定受控专项回归，通过本地函数断言或禁用模型后的浏览器回放测得，不能当作全量任务完成率、线上大模型成功率或 pass^5。历史 36 条混合版本样本通过 7 条（19.44%），29 条失败中有 18 条归于规划层 L3（62.07%）；历史基准没有冻结成单一版本。

六条样本上的评委 v1.2 校准仍未达标：维度一致率 14/24（58.33%），检查点一致率 14/18（77.78%），任务结论一致率 2/6（33.33%）。保留分歧和失败记录，不用专项满分替代整体评测结论。

详细方法和结果见 [评测说明](eval/README.md) 与各轮 `eval/agent-regressions/` 报告。个人简历、截图和密钥未纳入仓库；报告中的截图路径是本机留存证据。

## 当前限制

- 景点检索使用字段、关键词和字符片段匹配，不是向量嵌入检索。天气和闭馆状态仍未实时核实；临时调整根据用户提供的变化和本地候选景点执行。
- 大模型是可选项；需要你自行配置兼容服务的 API Key，并承担服务商的费用与数据处理规则。模型生成的编排理由仍需人工判断。
- 初版知识库覆盖北京、杭州、西安、成都、苏州、厦门、上海、广州和南京，共 60 个景点条目（上海、广州、南京各新增 8 个）；覆盖仍有限，没有匹配资料时不会编造行程。
- 自动天气安排只适用于天气服务返回覆盖的日期；更远日期会明确标为超出预报范围。
- 门票、库存、预约和开放时间来自本地知识库，可能过期，出行前要以景区官方信息核实。
- 跨城市需求会提示确认城市分配与城际交通，目前不生成统一跨城市行程。尚未实现完整的开放时间和预约可执行性自动校验。
- 地图服务可能把模糊地点解析到同名地点；路线展示的“地图匹配”地址必须核对。路线时长和费用是查询时的服务结果，不是承诺。
- 应用没有订票、下单、付款或证件提交功能，也不会替用户执行交易。
- 仅规划中国大陆景区。
